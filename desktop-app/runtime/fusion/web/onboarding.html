选择如何运行整套系统

① 单个 Agent

优点：装一个就能用，初始化 30 秒；只维护一份登录和密钥；五个角色行为一致，出问题好排查；只买一个 agent 的额度。

缺点：门下省和中书省同源——同一个模型审自己写的计划，封驳容易变成走过场；单点故障，这个 agent 限流或挂了整条链停；没法按角色分配成本，太子这种高频判定也得用贵模型；升级受制于单一厂商。

② 多个 Agent （推荐）

优点：门下省可以绑不同厂商，形成真正的独立审查；按能力分配，太子/尚书用便宜的、中书/工部用强的；贵模型只花在瓶颈位置；一个 agent 挂了可以换，不至于全停。

缺点：要装 2–3 个 agent，磁盘和密钥都多几份；初始化要逐个绑角色；不同品牌 prompt 行为有差异，调优成本更高；每个角色都配贵的，总价比单 agent 高。

绑定 Agent

推荐只是推荐，你可以自由改选已探测到的 Agent。

已有用户的实例需要管理员登录；一键安装始终需要管理员会话。

这套系统是什么


      

        三省六部制：把「决策—审核—执行」拆开互相制衡
        
三省六部制成型于隋、完备于唐，是把决策、审核、执行拆开互相制衡的中央官制。

        
中书省起草诏令，门下省审核并可封驳（驳回要退回重写），
           尚书省总领执行，下设六部：吏部（官吏任免考核）、户部（户籍财政）、
           礼部（礼仪科举外交）、兵部（军事）、刑部（司法刑狱）、工部（工程营造）。

        
它的精髓不是分工本身，而是门下省有权说「不准」——决策者不能自己批自己。

      


      

        本系统的五个角色
        

          

            
角色职责对应历史

            
              
太子判定请求是任务还是闲聊，规范化需求本系统扩展，非三省六部建制

              
中书省规划子任务、依赖顺序与验收标准中书省

              
门下省独立审查，可封驳并要求修订门下省

              
尚书省按依赖排序派发尚书省

              
工部真实读写文件、产出交付物工部

            
          

        

        
诚实说明：六部中目前只落地了工部作为执行单元；
          吏、户、礼、兵、刑五部是历史建制，本系统尚未拆分实现。

  1. 真干活，不是聊天——能读你给的文件、写真实文件、跑命令，产物有哈希可核对。
    2. 
          
  2. 每一步留痕——谁在什么时间、用哪个模型、以什么理由做了决定，全部可回溯。
    3. 
          
  3. 封驳是真的——门下省由不同厂商的模型担任时，坏计划会被打回并列出修订要求。

常见问题这套系统怎么解

            
              
AI 说「做完了」，其实没做产物落盘加 SHA-256 可核对，跑失败就标失败

              
同一个模型自己规划自己审门下省可绑不同厂商，同源时系统会警告

              
长任务跑飞、重复执行租约加令牌，越权写入被拒

              
成本失控 / 账单看不懂双层预算，未知成本不记 0

              
高风险动作没人把关离线私钥签名，签不了就走不完

              
换个模型要重写胶水角色绑定表，一行命令搞定
